# v0.4.0 主体体验：人生方格仪式

## 主体定义

财富自由指南灯的核心反馈不是一句 Toast，也不是数字从 100 变成 112。

真正的反馈是：用户亲眼看见自由边界移动。

收入或成本变化让整数自由天数增加时，镜头移动到边界，新获得的每一天从暗色逐格绽放为稳定金色；自由天数下降时，从边界反向逐格退回暗色。整个过程只表现已经由账本和数学内核计算出的 before / after，不参与计算。

## 点亮

`全局人生 → 追焦边界 → 放大 → 暗格逐个绽放 → 数字同步增加 → 镜头归位 → 新全局`

颜色路径保持单调走向最终颜色，避免脉冲结束时“又变暗再点亮”的假重复感。峰值只叠加短促暖白 bloom、光晕和轻微 scale。

## 熄灭

`全局人生 → 追焦最后拥有的自由日 → 放大 → 金色逐个经过暖褐/灰烬回到暗色 → 数字同步减少 → 镜头归位`

熄灭比点亮慢，表达“失去是安静的黯淡”，不是错误报警。因此不使用整页 shake、不使用手机震动，也不把方格做成刺眼危险红。

## FREE

只有从“剩余人生尚未全亮”第一次跨越到“剩余人生全部点亮”时触发。

显示：

- `FINANCIAL FREEDOM ACHIEVED`
- `FREE`
- `财 富 自 由`
- `你已点亮人生剩余的所有方格`

多层金色波纹向外扩散，默认保留足够时间让达成感成立，同时用户始终可以跳过。

## 滚动与实时渲染的边界

平时滚动页不承载可见实时 Canvas。静态人生方格是 Canvas 生成后的普通图片。

交易仪式使用另一张 Canvas，而且它固定在 viewport 的全屏层里。用户进入仪式时页面滚动被隔离；仪式结束后 Canvas 销毁。

这使两个要求不再冲突：

- 日常页面高速滑动必须稳定；
- 交易发生时方格必须真正实时运动。

## 验证标准

主体达到可继续做外围治理的最低条件：

1. `lit_count` 增加时只能点亮，减少时只能熄灭；
2. 动画变化数量必须严格等于 `abs(after.lit_count - before.lit_count)`；
3. Camera 能追随变化边界，并最终回到全局；
4. 20,000 格量级仍能完成实时渲染；
5. 320px 级小屏不能裁掉核心数字、舞台或跳过入口；
6. 动画失败不能回滚或伪造账本；
7. 返回首页前，静态方格必须与最终数据一致，失败时宁可显示重新生成，也不能显示旧图；
8. delta=0 不启动假仪式。
