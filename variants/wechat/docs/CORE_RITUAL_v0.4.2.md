# 财富自由指南灯 · 主体仪式定义 v0.4.2

本阶段只完成主体，不扩张周边治理。数学内核继续继承已经冻结的原始公式。

## 主舞台

交易先得到确定的 before / after。只有 `lit_count` 真正跨过整数自由日，才进入实时仪式。

1. 整个手机视口成为人生方格舞台，不再把 Canvas 放进一张“进度卡片”。
2. Camera 先从全局人生找到自由边界，约 600ms 追焦。
3. 点亮：单格约 2000ms，暗 → 暖金爆发 / bloom → 稳定金色。
4. 熄灭：单格约 2600ms，金色 → 暖褐 / 灰烬 → 暗格，逐格节奏约为点亮的 1.4 倍。
5. 第一格一开始发生视觉变化，语义反馈立即进入“正在点亮 / 黯淡”；自由天数数字必须等该格完整结束后才变化。
6. Camera 持续追着变化边界移动；最终约 1100ms 拉回整个人生。
7. 最终静态方格快照生成成功后才退出仪式。
8. 第一次跨越最后一格时进入全视口 `FREE / 财 富 自 由`。

## 节奏

恢复最初电脑版的触发节奏作为默认基准：

- ≤3 格：780ms / 格
- ≤8 格：540ms / 格
- ≤20 格：340ms / 格
- ≤60 格：180ms / 格
- ≤200 格：78ms / 格
- ≤800 格：26ms / 格
- >800 格：10ms / 格

熄灭触发间隔 ×1.4。移动端只在极端规模下设置 15 秒触发窗口上限；1000 格点亮/熄灭仍保持接近原版的完整节奏，而不是压缩成 5 秒左右。

## 视觉不变量

- 人生方格是主角，仪式期间不显示 dashboard 式进度条。
- Camera 放大后必须矢量重绘可见方格，禁止把低分辨率整图放大。
- 远景已点亮区域保留原版非常克制的整体暖光；放大后由单格 halo 接管。
- 点亮过程不得出现黑块、回退暗色或错误主题色。
- 熄灭不是警报，不用高饱和红色、不震动整页。
- `delta = 0` 不演假仪式。
- 数字、文字、最终快照都必须服从真实 before / after 数据。

## 已验证的本地主体

- 390×844 点亮 / 熄灭中途视觉状态
- 320×568 全视口舞台与反馈不裁切
- 点亮中途存在金色、暗格、bloom
- 熄灭中途存在暖褐 / 灰烬过渡
- 数字只在单格完成后推进
- 第一格开始时语义反馈立即进入进行态
- 1000 格点亮：本地 Chromium Canvas 约 13.7s / 753 帧
- 1000 格熄灭：约 18.3s / 1062 帧

这些是本地实时 Canvas 验证，不冒充微信开发者工具或真机结果。
