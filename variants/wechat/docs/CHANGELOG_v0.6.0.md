# v0.6.0 — 消费分类、分析与长期账本

V0.6.0 不改财富自由公式。它解决的是 V0.5.x 已经能“记账并换算自由时间”之后缺失的第二层问题：**这些生活消耗具体花在了哪里，长期记录会不会变得难读、难分析、难保存。**

## 1. 主分类：一笔支出只进入一个统计口径

生活消耗新增主分类：

- 正餐
- 饮料/零食
- 生活用品
- 交通
- 学习/工作
- 娱乐
- 医疗健康
- 住宿/通信
- 其他

主分类用于金额和百分比统计，因此每笔支出只允许一个主分类，避免同一笔钱被重复统计。

V0.5.x 历史账单没有分类事实，迁移后统一保留为 `未分类`，不会猜成“正餐”或其他类别。

## 2. 用户快捷标签：更细，但不重复计数

新增“分类与快捷标签”页面。用户可以在主分类下预设：

- 标签名称，例如 `日常吃饭 / 聚餐 / 约会`
- 默认备注（可选）
- 默认消费性质（可选）

记账时点一下快捷标签，就会把标签记录到该笔交易；有默认备注/性质时同步带入。实际金额仍必须按真实发生额输入，不提供自动套金额，避免把习惯价格误当真实支出。

快捷标签只负责描述和趋势筛选，不参与主分类百分比的重复计数。

## 3. 消费性质由用户自己判断

每笔生活消耗可选：

- 必要
- 可调
- 可省

它们不是系统自动推断。旧账和未判断的账保留为 `未设定`。

## 4. 周 / 月 / 年消费分析

新增“消费分析”页面：

- 本周期累计生活消耗
- 上一周期同期金额
- 金额与百分比变化
- 最大消费主分类
- 主分类金额 + 百分比横向比较
- 消费性质金额 + 百分比
- 单主分类趋势
- 单快捷标签趋势

粒度：

- 周：按天
- 月：按天
- 年：按月

周期比较使用“同期”而不是拿未结束的本月直接和完整上月比较。

## 5. 可读 CSV 与灾备 JSON 分工

完整 JSON 仍用于恢复，并升级为 Backup Schema v2，新增快捷标签和交易分类字段；仍兼容导入 v1 备份。

消费分析页新增本周期 CSV：

1. 周期、总支出、上一周期同期、变化；
2. 主分类金额和占比；
3. 消费性质金额和占比；
4. 日期 / 主分类 / 子标签 / 消费性质 / 金额 / 备注的逐笔明细。

因此“恢复数据”和“人直接阅读”不再由同一个文件勉强承担。

## 6. 长期账本：从单 key 改为按月分桶

V0.5.x 的全部交易都存在 `wfb.transactions`。V0.6.0 第一次安全读取时会自动迁移为：

```text
wfb.tx.index
wfb.tx.2026-07
wfb.tx.2026-08
wfb.tx.2026-09
...
```

迁移过程多 key 写入有回滚；写完索引后才移除旧单 key。旧数据语义保持不变。

历史页每次只把 100 条记录送进页面状态。消费分析只读取当前周期和上一周期所需月份。

## 7. 自动验证

`bash tests/run_all.sh` 当前包含全部 V0.5.x 回归和 V0.6.0 新增验证。

新增重点：

- 主分类 / 快捷标签 / 消费性质统计；
- 月度同期比较；
- 单分类与单标签趋势；
- CSV 可读结构；
- Backup v2 + v1 兼容；
- 快捷标签备份恢复；
- 1000 条旧账自动分桶迁移；
- 带长中文备注的 10,000 条账本在 1 MB 单 key 限制模拟下读写；
- 10,000 条历史页只返回首 100 条给视图。

本地测试不等于微信 iOS / Android 真机最终验收。提审前仍要在微信开发者工具和至少一台 iOS、一台 Android 上验证新增页面、Canvas 趋势图、CSV 转发和旧数据迁移。
