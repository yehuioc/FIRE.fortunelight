# v0.3.2 Bug 根因分析

## 1. 人生方格快速滚动时拖影 / 延迟归位

v0.3.1 把 Canvas 2D 直接作为主页可见内容。用户快速滚动页面时，Canvas 内容在微信运行时出现相对卡片短暂滞后，最后再归位。

修复：Canvas 只做绘制；通过 `wx.canvasToTempFilePath({ canvas })` 导出后由普通 `image` 展示。可见方格不再依赖 Canvas 的滚动合成表现。

## 2. 上手版支出 ¥50 / ¥1,100，方格完全不动

这不是单纯“忘记 redraw”。v0.3.1 的数据确实重新计算了，但上手版错误复用了高级原始公式：

- 日均成本被手动固定为 ¥100，所以支出不会抬高分母；
- 起始资产 ¥10,000 是固定资产桶；
- 支出产生负净储蓄，而原始公式只在 `net_savings > 0` 时计算收入自由天数；
- 因此资产自由始终 `floor(10000/100)=100`，支出 ¥50、¥1,100 都不会改变方格。

这符合高级原始公式，但不符合“上手版每笔收支立即改变当前余额”的产品承诺。

修复：
- 高级自主版继续使用原始公式，不动；
- 上手版明确成为余额入口：`current_assets = starting_assets + income - expense`；
- 方格按 `floor(current_assets / manual_daily_expense)` 即时重算。

## 3. “没有跨过完整一天，但口径已同步”没有意义

这段反馈没有回答用户最关心的“为什么不动、还差多少”。

修复：
- 有变化：明确 `+N / -N 格`、前后自由天数、当前资金；
- 无变化：给出距离下一格还差的具体金额。

## 4. 整机震动反馈廉价且干扰

v0.3.1 每笔交易调用 `wx.vibrateShort`。这并没有帮助用户理解点亮/熄灭，反而让整个设备震动，和产品的“仪式感”不匹配。

修复：完全删除；静态变化高亮快照承担反馈。
